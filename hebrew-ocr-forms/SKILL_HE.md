# זיהוי תווים (OCR) לטפסים בעברית

## הנחיות

### שלב 0: להחליט אם בכלל צריך OCR

**קודם בודקים אם יש שכבת טקסט.** רוב המסמכים ש-gov.il מנפיק היום הם קובצי PDF דיגיטליים: נסח הטאבו מרשם המקרקעין, טופס 106 שיוצא מתוכנת השכר, אישורי ביטוח לאומי שהורדו מהאזור האישי. מריצים `pdftotext -layout file.pdf -` (מחבילת poppler); אם יוצאת עברית אמיתית, עובדים עם הטקסט הזה ומדלגים על OCR לגמרי, כי OCR יכול רק לאבד תווים שכבר מדויקים. מחלק מקובצי ה-PDF העברית יוצאת בסדר חזותי (הפוך), ואז צריך לסדר אותה מחדש לפני התאמת תוויות. רק עמודים שהם תמונה בלבד (סריקות, צילומי טלפון) עוברים את שלבים 2-3. בעמוד של רשם המקרקעין כתוב שנסח מוכר כמסמך מקורי רק בצורה דיגיטלית ולא כשהוא מודפס, אז עדיף לבקש את ה-PDF במקום לסרוק תדפיס.

**אם אתם יכולים לקרוא תמונות בעצמכם** (סוכן עם יכולת ראייה), אפשר לקרוא עמוד ישירות בלי להתקין Tesseract, אבל עדיין מריצים על מה שקראתם את הבדיקות הדטרמיניסטיות משלב 6 (ספרת ביקורת של ת.ז., סכום חלקי הבעלים).

**פרטיות.** בעמודים האלה יש מספרי זהות, שכר, מס ונתוני גמלאות, וזה מידע אישי לפי חוק הגנת הפרטיות (תיקון 13 בתוקף מ-14 באוגוסט 2025, עם סמכויות אכיפה מורחבות). ברירת המחדל היא Tesseract מקומי. לפני ששולחים עמודים לשירות OCR או למודל שפה בענן:
- מוודאים שבעל המידע מסכים, ולעולם לא שולחים מכתבי נכות או לידה מביטוח לאומי (פרטים רפואיים) בלי הסכמה מפורשת שלו;
- זוכרים ששירותי הענן הגדולים עשויים לעבד את המידע מחוץ לישראל, נושא שמוסדר בתקנות הגנת הפרטיות (העברת מידע אל מאגרי מידע שמחוץ לגבולות המדינה), ושמשרד ששומר סריקות כאלה כפוף גם לתקנות הגנת הפרטיות (אבטחת מידע);
- מסתירים מספרי זהות בכל שדה שלא צריך, ומוחקים עמודים שהועלו ותמונות ביניים בסוף העבודה;
- במשרדי עורכי דין ורואי חשבון, מסמכי לקוחות כפופים גם לחובת הסודיות המקצועית.

**הפלט הוא תעתיק לא רשמי.** כל ערך שהסקריפטים מחזירים הוא קריאת OCR, לא הרשומה של הגוף המנפיק; ב-JSON יש שדה `notice`, וקובץ ה-CSV של הנסח מסתיים בשורת `notice` עם אותה הערה. לא מציגים את ה-CSV כאילו הוא הנסח עצמו, ולא מפרשים מה המשמעות של רישום (הערת אזהרה, עיקול, צו) לעסקה.

### שלב 2: עיבוד מקדים של התמונה הסרוקה

תסתכלו על `scripts/preprocess_image.py` לפייפליין העיבוד המקדים המלא. השלבים העיקריים:
1. המרה לגווני אפור (ואם יש מסגרת כהה של הסורק, חיתוך שלה קודם עם `--remove-borders PX`, כדי שלא תטה את הערכת הזווית)
2. יישור - טפסים ישראליים לפעמים נסרקים בסיבוב קל; הערכה מעל 15 מעלות נדחית במקום ניחוש. ההערכה מתבססת על כל הדיו בעמוד, ובעמודי הבדיקה הסינתטיים שלנו חותמת או חתימה גדולה סובבו עמוד ישר בכ-1 עד 3 מעלות; בודקים את הפלט ומשתמשים ב-`--no-deskew` אם צריך
3. הסרת רעש (non-local means, `--denoise-strength`, ברירת מחדל 15)
4. בינאריזציה רק לפי בקשה (`--binarize`, עדיף יחד עם `--denoise-strength 20`). המנוע Tesseract עושה בינאריזציה בעצמו, וסף מסתגל על סריקה גרעינית הופך את הגרעיניות לנקודות שהוא קורא כאותיות; בסריקות הבדיקה שלנו הפלט בגווני אפור קרא את כל השדות והפלט הבינארי איבד חלק מהם
5. צילומי טלפון וסריקות ברזולוציה נמוכה: הפייפליין הזה לא מתקן פרספקטיבה או עיקום של הדף. הסקריפט מזהיר כשהתמונה קטנה בהרבה מעמוד A4 ב-300 DPI, וכשגובה האותיות החציוני קטן מדי ל-OCR (בעמודי הבדיקה הסינתטיים שלנו כ-4 פיקסלים נכשלו וכ-7 נקראו היטב; האזהרה מופיעה מתחת ל-8 פיקסלים), וכך גם צילום מרחוק במצלמה של 12 מגה-פיקסל נתפס. מבקשים סריקה חוזרת ב-300 DPI או צילום קרוב יותר באפליקציית סריקה שמיישרת את הדף

### שלב 3: הרצת OCR בעברית עם Tesseract

תסתכלו על `scripts/extract_form_fields.py` לפייפליין החילוץ המלא.

**הגדרות Tesseract לטפסים בעברית:**

```python
config = (
    '--oem 1 '          # LSTM neural net (best for Hebrew)
    '--psm 6 '          # Assume uniform block of text
    '-l heb+eng '       # Hebrew + English (forms have both)
    '-c preserve_interword_spaces=1'  # Keep spacing for field alignment
)
```

- תכללו גם heb וגם eng כי טפסים מכילים גם עברית וגם אנגלית/מספרים; בטפסים דו-לשוניים עברית/ערבית מוסיפים `ara` (`--lang heb+ara+eng`)

### שלב 5: טיפול ב-RTL וטקסט דו-כיווני

```python
import unicodedata

def normalize_bidi_text(text):
    """Normalize bidirectional text from Hebrew OCR output."""
    lines = text.split('\n')
    normalized = []
    for line in lines:
        # Strip bidi control characters
        clean = ''.join(
            c for c in line
            if unicodedata.category(c) != 'Cf'
        )
        clean = ' '.join(clean.split())
        if clean:
            normalized.append(clean)
    return '\n'.join(normalized)
```

הסירו ניקוד לפני התאמת מחרוזות מדויקת. הפונקציה `normalize_bidi_text()` מסירה רק תווים מקטגוריית Unicode מסוג `Cf` (פורמט). ניקוד וטעמים בעברית (בטווח U+0591 עד U+05C7) שייכים לקטגוריה `Mn` (סימן לא-רווח), אז הם שורדים את הסינון הזה. אם טופס סרוק מכיל במקרה טקסט מנוקד, או שמנוע ה-OCR ממציא סימנים תועים, התאמת מחרוזת מדויקת או regex של מילת מפתח כמו `"גוש"` תיכשל בשקט מול `"גּוּשׁ"`. כדאי להסיר ניקוד במפורש לפני התאמת מילות מפתח:

```python
import re

# U+0591-U+05C7 minus the four punctuation marks inside it: maqaf U+05BE
# (the Hebrew hyphen, as in תת־חלקה), paseq U+05C0, sof pasuq U+05C3,
# nun hafukha U+05C6. Stripping the whole range would delete the maqaf.
NIKUD_RE = re.compile('[\u0591-\u05BD\u05BF\u05C1\u05C2\u05C4\u05C5\u05C7]')

def strip_nikud(text):
    """Remove Hebrew diacritics so keyword regexes match reliably."""
    return NIKUD_RE.sub('', text)
```

נרמלו אותיות סופיות בהתאמה. בעברית יש חמש אותיות בצורה סופית: ך ם ן ף ץ. אלה אותן אותיות כמו כ מ נ פ צ אבל מקודדות כנקודות קוד נפרדות. בדרך כלל OCR שומר אותן נכון, אבל לוגיקת התאמת מילות מפתח והתאמה מקורבת עלולה להישבר: תווית שזוהתה עם צורה סופית לא תהיה שווה למונח חיפוש שנכתב עם הצורה הרגילה, ולהפך. כשמתאימים תוויות שדה, נרמלו את שני הצדדים לצורה אחת קודם:

```python
SOFIT_MAP = {'ך': 'כ', 'ם': 'מ', 'ן': 'נ', 'ף': 'פ', 'ץ': 'צ'}

def normalize_sofit(text):
    """Fold final-form letters to their medial forms for matching."""
    return ''.join(SOFIT_MAP.get(ch, ch) for ch in text)
```

הפעילו את `strip_nikud()` ואת `normalize_sofit()` רק על מפתח ההתאמה, אף פעם לא על הערך שאתם שומרים או מציגים, האותיות הסופיות והניקוד הם חלק מעברית תקינה וחייבים להישמר בפלט.

### שלב 6: אימות הנתונים שחולצו

אחרי החילוץ, תאמתו את שדות המפתח. את שני הראשונים הסקריפטים כבר עושים, וההצלבה של ת.ז. בהמשך היא עליכם:
- **מספרי ת.ז.:** תריצו אלגוריתם אימות ת.ז. ישראלית (ספרת ביקורת). הסקריפטים מקבלים 9 ספרות, או 8 כשהאפס המוביל לא הודפס (מסומן `*_padded`); קריאה קצרה יותר נחשבת קטע ולא מושלמת באפסים, כי קטע שהושלם יכול לעבור את ספרת הביקורת במקרה
- **ציון ביטחון:** `extract_form_fields.py` מחזיר `ocr_confidence` (ביטחון ממוצע למילה והמילים שמתחת ל-60) ו-`field_confidence` (הביטחון הנמוך ביותר מבין מילות ה-OCR שמהן נקרא כל שדה מספרי); כל שדה מתחת ל-60 עובר לבדיקה אנושית
- **תאריכים:** תאמתו פורמט DD/MM/YYYY וטווחי תאריכים תקינים
- **סכומים:** תבדקו שהשדות הנומריים פוענחו נכון, בלי ארטיפקטים של OCR בספרות
- **גוש/חלקה:** תאמתו פורמט מספרי וטווחים הגיוניים
- **הצלבה:** אם ת.ז. מופיעה בכמה שדות, תוודאו שהיא עקבית

## דוגמאות

### דוגמה 1: עיבוד נסח טאבו לגיליון
המשתמש אומר: "תפרק את נסח הטאבו הסרוק הזה לאקסל"
תוצאה: עיבוד מקדים של התמונה, הרצת OCR בעברית, זיהוי שזה נסח טאבו, ואז הרצת `tabu_to_spreadsheet.py` שמנרמל את החלקים החוזרים לשורות (שורה לכל בעלים עם החלק שלו, שורה לכל משכנתא ושורה לכל הערת אזהרה), אימות כל ת.ז., וכתיבת CSV מוכן לאקסל בקידוד UTF-8 עם BOM. סימון לבדיקה אנושית אם סכום החלקים של הבעלים לא מגיע לבשלמות.

### דוגמה 2: עיבוד אצוות של טפסי מס
המשתמש אומר: "יש לי 50 טפסי 106 סרוקים - חלץ נתוני שכר ומס"
תוצאה: קודם מנסים `pdftotext` על כל קובץ (טפסי 106 שיוצאו מתוכנת שכר הם בדרך כלל PDF עם טקסט). לסריקות עוברים על הקבצים בלולאה: עיבוד מקדים, הרצת `extract_form_fields.py --form-type tofes_106`, שמירת `field_confidence` עם כל רשומה, אימות ת.ז. העובד, ואיסוף ה-JSON ל-CSV אחד. כל רשומה עם שדה מתחת ל-60 או עם `rows_without_amount` לא ריק עוברת לבדיקה ידנית.

### דוגמה 3: בעיות איכות OCR
המשתמש אומר: "ה-OCR לא קורא את הטקסט בעברית נכון"
תוצאה: אבחון של העיבוד המקדים - בודקים רזולוציית תמונה (Tesseract עובד הכי טוב ב-300 DPI ומעלה), מאמתים יישור, משווים את פלט ברירת המחדל בגווני אפור מול `--binarize`, מעלים את `--denoise-strength` בסריקות גרעיניות, מנסים מצבי PSM שונים, בודקים שחבילת השפה העברית מותקנת.

## משאבים מצורפים

### סקריפטים
- `scripts/preprocess_image.py` - הכנת תמונות של טפסים ישראליים סרוקים ל-OCR: המרה לגווני אפור, חיתוך שוליים אופציונלי, יישור (`--no-deskew` כדי לדלג), הסרת רעש (non-local means), ובינאריזציה מסתגלת ושיפור ניגודיות CLAHE לפי בקשה. מסרב לקבל PDF ומפנה ל-`pdftotext` או ל-`pdftoppm`. הרצה: `python scripts/preprocess_image.py --help`
- `scripts/extract_form_fields.py` - הרצת Tesseract OCR בעברית על תמונה של עמוד אחד וחילוץ שדות. מזהה אוטומטית נסח טאבו, טופס 106, 806/857, 102, אישור ניכוי, אישורי ביטוח לאומי ורישיון רכב. יש מחלצי שדות ייעודיים לנסח (מפתח הנכס והבעלים הראשון) ולטופס 106; לכל סוג אחר מוחזרים מספרי הזהות (עם תוצאת ספרת הביקורת), התאריכים והסכומים בלי תוויות, ואתם ממפים אותם בעזרת `--raw-text`. תמיד מחזיר `ocr_confidence` ו-`field_confidence`. הרצה: `python scripts/extract_form_fields.py --help`
- `scripts/tabu_to_spreadsheet.py` - הופך את טקסט ה-OCR של נסח טאבו מלא ל-CSV מנורמל ומוכן לאקסל: שורה לכל בעלים (עם החלק), משכנתא והערת אזהרה, ממופתח לפי גוש/חלקה/תת-חלקה. שומר את החלקים כמו שהם, מוציא מספרי שטר (12345/2015/1) מעמודת החלק, ומתריע כשסכום חלקי הבעלים לא שווה בדיוק לבשלמות, כשלכותרת של חלק אין שורות מתחתיה, כשת.ז. נכשלת בספרת הביקורת או הושלמה באפסים, או כששום דבר לא פוענח. הרצה: `python scripts/tabu_to_spreadsheet.py --example`

### קובצי עזר
- `references/israeli-form-types.md` - קטלוג מפורט של סוגי טפסים ממשלתיים ישראליים (טאבו/מקרקעין, טפסי רשות המסים, מסמכי ביטוח לאומי) עם תיאורי שדות, ביטויי regex לחילוץ, כללי אימות ת.ז., פורמטי תאריך/מטבע, וטיפים ל-OCR לפי פריסת הטופס. תסתכלו בו כשאתם מזהים טופס לא מוכר או בונים לוגיקת חילוץ שדות למסמך מסוים.

## מלכודות נפוצות
- דיוק OCR בעברית יורד משמעותית בטקסט בכתב יד, במיוחד באותיות ו', ז' ו-י' שנראות דומות. תמיד תכללו ציוני ביטחון ותסמנו תווים עם ביטחון נמוך.
- טפסים ממשלתיים ישראליים סרוקים לפעמים מכילים טקסט מעורב עברית וערבית. סוכנים עלולים לזהות את החלקים הערביים כעברית או לדלג עליהם לגמרי. שתי השפות RTL אבל בטווחי Unicode שונים; מתקינים את נתוני `ara` של Tesseract ומעבירים `--lang heb+ara+eng`.
- מספרי תעודת זהות שחולצו ב-OCR צריכים אימות עם אלגוריתם ספרת הביקורת, כי שגיאות OCR של ספרה בודדת נפוצות. למספרי טלפון אין ספרת ביקורת; בודקים רק שהם בפורמט הצפוי.
- הרבה טפסים ישראליים משתמשים בהדפסת מטריצת נקודות (dot-matrix) בעברית, שיש לה דיוק OCR נמוך יותר מטקסט מודפס בלייזר. סוכנים עלולים לדווח על ביטחון גבוה מדי במסמכים ממשלתיים ישנים.
- המנוע Tesseract עלול לשנות סדר של רצפי ספרות בתוך שורת RTL. מספר כמו ת.ז. בת 9 ספרות או סכום בחשבונית שמודפס בתוך משפט עברי עלול לחזור עם קבוצות הספרות מעורבבות, גם כשכל ספרה בנפרד זוהתה נכון. אל תסמכו על הסדר הגולמי משמאל לימין של מספרים שחולצו משורה מעורבת עברית/ספרות, עגנו כל מספר מחדש לתווית השדה שלו ואמתו מחדש עם כללי ספרת ביקורת או טווח.
- המנוע Tesseract משמיט את הרווח בין מילה עברית למספר שצמוד אליה ("טופס106", "שנת מס2025", "בתאריך15/03/2025") ובין שני מספרים ("04221,340"). מתאימים תוויות אחרי הסרת רווחים, לא משתמשים ב-`\b` בין עברית לספרות, ומפרידים קודי שדה ידועים מהסכום לפני הפענוח.
- הסקריפטים המצורפים מקבלים רק קובץ תמונה בודד. הרבה טפסים ישראליים הם קובצי PDF רב-עמודיים (חבילת טופס 106, נסח טאבו רב-דפי). המירו כל עמוד PDF לתמונה קודם, למשל עם `pdf2image` (`convert_from_path`) או `pdftoppm`, ואז הריצו עיבוד מקדים ו-OCR לכל עמוד ומזגו את השדות שחולצו. אל תעבירו PDF גולמי ל-`preprocess_image.py` או ל-`extract_form_fields.py`.

## פתרון בעיות

### שגיאה: "חבילת שפה עברית של Tesseract לא נמצאה"
סיבה: קובץ traineddata בעברית לא מותקן
פתרון: תתקינו עם `sudo apt-get install tesseract-ocr-heb` (Ubuntu) או `brew install tesseract-lang` (macOS). אימות עם `tesseract --list-langs`.

### שגיאה: "פלט ה-OCR משובש או הפוך"
סיבה: שתי סיבות שאומתו. (1) סדר דו-כיווני בשורות שמערבבות עברית ומספרים. (2) גרעיניות של הסורק שהפכה לנקודות בבינאריזציה: בסריקות הבדיקה הגרעיניות שלנו התמונה הבינארית החזירה עמודים של ג'יבריש לטיני ועברי, והתמונה בגווני אפור אחרי הסרת רעש קראה את כל השדות.
פתרון: ל-(1), תשתמשו ב-`normalize_bidi_text()` ותעגנו כל מספר מחדש לתווית שלו; תבדקו שהתמונה לא מראתית. ל-(2), תריצו את `preprocess_image.py` בלי `--binarize` (ברירת המחדל), או עם `--binarize --denoise-strength 20`.

### שגיאה: "דיוק נמוך בחלקים מסוימים של הטופס"
סיבה: איכות סריקה ירודה, חותמות/חתימות חופפות לטקסט, רקעים צבעוניים
פתרון: תגבירו את העיבוד המקדים - הסרת רעש חזקה יותר, חיתוך לאזורים ספציפיים בטופס, חילוץ מבוסס ROI לפריסות טפסים מוכרות.
